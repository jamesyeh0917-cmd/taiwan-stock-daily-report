# 回測校準與 price-in 判斷

兩個機制讓評分不只是每天憑感覺打分：

## 一、price-in 判斷（每次 `full` 執行）

對每個優先題材的**主要催化劑**（已發生的那個），跑：

```
python scripts/price_in.py --code <代表個股> --event-date <催化劑發生日>
```

輸出：事件前漂移、事件當日報酬、事件後報酬、相對大盤超額、`priced_in_heuristic_0_100`、一句 `reading`。

用途：
- 題材排名 §10：`priced_in ≥ 70` → 在「是否已被價格反映」欄明確標「大部分已反映」，題材分的「估值與擁擠度」維度扣分。
- 個股 §11：候選股的「已被反映程度」欄填此結果。
- 若催化劑尚未發生（未來事件），不跑 price_in，標「催化劑未發生」。

一天最多對 3 個優先題材各跑 1–2 檔代表股，避免 FinMind 額度。

## 二、回測校準（每週一次，建議週一或每月 1 日的 `full` 執行）

### 步驟

1. 從「候選股追蹤」資料庫查出 `報告日` 在 **65 個日曆日以前**、且尚未評估過的列，取
   `代號 / 報告日 / 狀態 / 淨分 / 當日收盤價 / 題材`，匯出成 JSON 陣列存 `/tmp/calls.json`：
   ```json
   [{"code":"2454","date":"2026-06-10","status":"WATCH","net_score":68,"entry_close":1234.0,"theme":"AI 伺服器"}]
   ```
2. 跑：
   ```
   python scripts/backtest.py --calls /tmp/calls.json --output /tmp/backtest.json
   ```
3. 讀 `by_status`、`by_score_bucket`、`calibration_notes`。

### backtest.py 算什麼

- 每筆呼叫：FinMind 抓收盤序列 → 5／20／60 交易日後的前瞻報酬 + 相對 TAIEX 超額報酬。
- 依 `狀態` 分桶：各桶的樣本數、平均報酬、命中率（>0 佔比）、平均超額、贏大盤比率。
- 依 `淨分` 分桶（75+／60–74／<60）：同上。
- `calibration_notes`：機械式檢查，例如
  - PRIORITY_RESEARCH 的 20 日超額 ≤ WATCH → 「評分未有效區分」
  - 淨分 75+ 命中率 ≤ 60–74 → 「評分與前瞻報酬相關性弱」
  - ABSTAIN 事後平均超額為正 → 「排除規則過嚴」

### 校準動作

把 `calibration_notes` 寫進當週報告的新章節「§14.5 回測校準」，並：
- 若連續 2 次校準都指出評分無效區分 → 在 stock-screening.md 的維度配分上做保守調整（記錄於報告，不自行改檔；由使用者確認後改）。
- 樣本 < 15 筆 / 每桶 < 5 筆 → 只呈現數字，不下校準結論。

### 注意

- 這是**校準輸入給人看**，不是自動最佳化。不得用回測結果反推出「買進」訊號。
- 前瞻報酬用收盤對收盤，無交易成本與滑價，僅供相對比較。
- 樣本永遠偏誤（只評估進過候選池的標的），結論僅限「我的評分有沒有區分力」。
