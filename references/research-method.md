# 研究方法與時間契約

## 輸入契約

先把使用者問題正規化為：

| 欄位 | 預設值 | 說明 |
|---|---|---|
| `analysis_as_of` | 見下方「排程／每日模式」 | 所有資料的可用截止線 |
| `cadence` | ad-hoc | `ad-hoc` 或 `daily`（排程） |
| `focus_country` | Taiwan | 主報告國家 |
| `global_scope` | US, China, Euro Area, Japan | 全球比較範圍 |
| `history_window` | 5 years | 歷史分位與標準化比較期間 |
| `tactical_horizon` | 1–4 weeks | 新聞、事件與市場驗證期間 |
| `strategic_horizon` | 3–12 months | 景氣、政策與獲利傳導期間 |
| `investment_universe` | TWSE/TPEx common stocks | 預設股票池 |
| `objective` | research screening | 一般研究，不做個人化配置 |

若使用者指定日期，將該日期與時區轉為明確截止時間；不要偷用截止時間之後發布的資料。

## 排程／每日模式的時間基準

- `cadence = ad-hoc`：`analysis_as_of` = 執行當下（Asia/Taipei）。
- `cadence = daily`：`analysis_as_of` = 「最近一個已收盤的台股交易日 15:00 Asia/Taipei」，不是排程觸發的掛鐘時間。這樣早上 8 點跑和晚上 8 點跑，對「最新盤後資料」的定義一致。
  - 若排程在交易日 15:00 前觸發，基準日退到前一個交易日。
  - 週末與國定假日以 `scripts/fetch_market_snapshot.py` 回傳的 `freshness.expected_last_trading_day` 為準。
- **建議排程時點：交易日隔天（T+1）08:00 Asia/Taipei，涵蓋 T 的收盤。** 此時 TWSE 與 TPEx 的 OpenAPI 都已穩定發布 T 日資料，`freshness.stale` 應為 false；報告以「T 日收盤」為基準完全合理。當天（T+1）盤中或盤後跑，openapi 鏡像常只到 T-1，會觸發新鮮度閘門。
  - 若 T+1 08:00 跑而 `freshness.stale` 仍為真（鏡像延遲），照新鮮度規則揭露，並可用 macro-fetch / 財經媒體補一個帶時間戳的 TAIEX 收盤點。
- 兩種模式都一樣：`analysis_as_of` 之後才發布的總經或新聞資料不得進入報告。

## 行情新鮮度閘門

`fetch_market_snapshot.py` 輸出的 `freshness` 區塊是強制檢查點：

| 觀察 | 處理 |
|---|---|
| `stale = false`、`status = ok` | 正常，台股章節標為當日盤後 |
| `stale = true` | 台股章節一律標「YYYY-MM-DD（前 N 個交易日）盤後資料」，揭露落後天數；情境與題材不得倚賴「今日」價量，戰術期催化劑順延 |
| TWSE 與 TPEx 資料日不同 | 不合併市場廣度、成交值、漲跌家數；兩市分開敘述 |
| `errors` 非空 | 列出抓取失敗的來源，對應章節標為缺資料，不用舊值或猜測填補 |
| `market_aggregate_recent` 與 `markets` 的大盤數字明顯不一致 | 以 FMTQIK（大盤統計）為準並註明差異 |

盤後資料落後時，若仍要對「昨日／今日」大盤指數表態，只能另用可信媒體或交易所即時頁面補一個帶時間戳的點，並標為 D 級佐證。

## 使用者要求到報告的固定管線

```text
使用者問題
  → 判斷國家、期間、指標及分析目的
  → 設定 analysis_as_of 與資料可用截止線
  → 取得官方資料、資料期、首次發布與修訂時間
  → 比較實際值、事前預期、前值與歷史區間
  → 分開記錄事實、推論、假說及反證
  → 產生基準／樂觀／悲觀三種情境
  → 建立總經與政策到產業、企業的傳導鏈
  → 評分題材，再評分個股
  → 列出證據、反證、不確定性、失效條件與來源
  → 輸出 PRIORITY_RESEARCH／WATCH／ABSTAIN
```

## 證據帳本欄位

每筆核心證據至少保存：

```text
region
indicator_or_event
observation_period
actual_value
consensus_value
consensus_timestamp
previous_as_first_published
previous_latest_revised
historical_percentile_or_zscore
unit
seasonal_adjustment
release_timestamp
retrieved_at
source_url
evidence_tier
data_quality_warning
```

禁止把 `previous_latest_revised` 當成當時可知的前值做歷史事件研究。若只能取得最新修訂序列，明確標為修訂後資料。

## 指標解讀順序

1. 確認單位、名目／實質、年增／月增、季調與年化口徑。
2. 比較實際值與事前預期，計算驚喜方向；無共識則跳過。
3. 比較前值，指出前值是否被修訂。
4. 放入近 5 年歷史分位或 z-score；結構轉折時縮短期間並說明。
5. 檢查不同指標是否同向，以及領先、同時、落後關係。
6. 提出至少一個替代解釋和一個可觀察反證。
7. 指定下一個會提高或降低信心的資料點。

不要用單一數據直接宣告景氣轉折。至少要求兩類獨立證據，例如需求與生產、通膨與薪資、政策與信用條件。

## 新聞與政策處理

- 分開記錄「事件發生時間」與「新聞發布時間」。
- 區分已生效、已通過、正式提案、徵詢意見、官員發言與媒體傳聞。
- 以政策原文確認適用對象、門檻、金額、生效日、落日條款與執行機關。
- 將直接影響、第二階影響與市場敘事分開。
- 若標題與內文、官方文件或其他可信來源不一致，以原始文件為準並揭露差異。

## 三情境規則

三個情境機率合計 100%。基準情境通常是目前證據最一致的路徑，不必機械固定為 60%。每個情境都要包含：

- 戰術期與策略期假設。
- 成長、通膨、政策與金融條件方向。
- 對台灣出口、台幣、利率、產業訂單與獲利的傳導。
- 2–5 個可觀測驗證指標。
- 明確失效條件。
- 可能受益與受損題材，不先指定股票。

情境不是預言；若無法定義失效條件，該情境不可用。

## 時間、回測與執行限制

- 在 `analysis_as_of` 後才發布的資料不得進入報告。
- 若資料在截止線後才被擷取，只能在原始發布時間、資料期與不可變版本足以證明其在截止線前已公開時，作為「事後擷取的當時可得資料」使用；必須揭露擷取晚於截止線。截止線後產生的快照本身不能證明快照內容在截止線前完全相同。
- 盤後資料只能支持盤後形成的研究結論；若模擬交易，最早進場時間為下一交易日開盤後。
- 不以同日收盤價假設可成交，不使用未來補值，不用今日成分股回填歷史股票池。
- 對 5 日或更長報酬標籤做研究時，使用 walk-forward、purge／embargo、訓練期內 fit 與不可變預測快照。
- 未完成歷史驗證、前向驗證、成本與滑價測試時，結論保持研究用途。

## 信心等級

- `高`：至少兩個獨立 A/B 級來源同向，資料新鮮，口徑一致，反證有限。
- `中`：主要來源可靠，但樣本短、修訂風險、傳導時間或跨來源口徑仍不確定。
- `低`：依賴二手新聞、缺少公司曝險或估值資料、來源衝突，或關鍵指標尚未發布。

信心低不等於相反方向；應降低狀態至 `WATCH` 或 `ABSTAIN`。
